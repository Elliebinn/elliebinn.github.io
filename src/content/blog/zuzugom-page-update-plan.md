## 수정 1: "04. 스코프 판단" 섹션 확장

### 위치
"4가지 핵심 설계 결정 > 04. 스코프 판단" 하단

### 현재 상태
IN/OUT 리스트만 존재 (v1 시점 스냅샷)

### 추가할 내용

기존 IN/OUT 리스트 아래에 "v2에서 검증한 것" 소제목 추가:

```
#### v2 — 제약이 풀린 뒤

**계좌 연동**: v1에서는 증권사 OpenAPI가 사업자만 쓸 수 있어서 손도 못 댔다.
v2에서 KIS(한국투자증권) OAuth를 직접 연동해서 잔고 자동 조회까지 됐다.
OCR은 진입장벽 없이 시작하는 용도로 남기고, KIS는 실시간 동기화 용도로 나눴다.

**자동 매매**: KIS 연동하고 나니 모의투자 주문까지 돌아가긴 했다.
그런데도 실매매는 안 열었다.
이유는 처음과 같다 — 이건 "대신 해주는 도구"가 아니라 "판단을 돕는 도구"니까.
```

### PM 관점 효과
- "못 만들어서 뺐다"가 아니라 "만들 수 있는데도 안 여는 판단"으로 읽힘
- 제약 수용 → 부분 해소 → 그래도 안 여는 것. 시간축이 보임
- 기술적으로 되는 것과 제품적으로 맞는 것은 다르다는 걸 보여줌

## 수정 2: "실사용 피드백과 반복" 섹션 끝에 추가

### 위치
피드백 사례 4 (한국 ETF 가격 0원) 다음

### 추가할 내용

```
#### 피드백이 만든 기능: 포트폴리오 브리핑

피드백을 고치면서 보니, 부모님은 앱을 "직접 분석"하지 않았다.

복잡한 화면을 단순하게 바꿔도 종목 검색 같은 능동적 행동은 안 일어났다.
그래서 열면 바로 답이 있는 구조로 바꿨다.

홈 화면 자체가 AI 모닝 브리핑이다.
열면 "오늘 당신의 포트폴리오" — 뭐가 바뀌었고, 왜 바뀌었고, 주의할 것.
며칠 안 열어도 날짜별로 흐름을 따라갈 수 있고, 분기마다 운용리포트가 나온다.

"딸이 정리해서 알려주는 것 같다"가 목표한 경험이다.
```

### PM 관점 효과
- 부모님으로 시작한 이야기가 여기서 자연스럽게 닫힘
- 기능을 더 만든 게 아니라, 사용자 행동에 맞게 구조를 바꾼 것
- "쓰게 만드는" 대신 "안 써도 되는" 방향으로 간 판단이 보임

## 수정 3: "현재 상태 & 다음 단계" 섹션 재편

### 위치
기존 "현재 상태 & 다음 단계" 전체 교체

### 변경할 내용

```
### 가설에서 검증으로

| v1에서 세운 가설 (당시 Next Steps) | v2 결과 |
|----------------------------------|---------|
| 실사용자 검증 필요 | 부모님 실사용 중. 피드백 → 당일 수정 사이클 반복 |
| 아침 브리핑 | 완료. 홈 = AI 모닝 브리핑 + 날짜별 히스토리 + 계좌 탭 |
| Claude API 전환 | 미전환. Haiku로 속도 개선, 비용 추적 중 |
| 계좌 연동 불가 (제약) | KIS OAuth 연동 완료 — 잔고 자동 동기화. OCR과 역할 분리 |

### 현재 기능 범위

- 6개 전문 에이전트 분석 + Supervisor 종합 시그널
- 4인 투자 페르소나 토론 + Q&A
- OCR 포트폴리오 등록 + KIS 잔고 자동 연동
- AI 모닝 브리핑 (홈 = 오늘의 포트폴리오 요약)
- 포트폴리오 브리핑 히스토리 (날짜별 + 계좌별)
- 분기 운용리포트
- 한국 + 미국 종목 동시 지원 (KRX 전체 + NASDAQ/NYSE)
- 3단 데이터 폴백 체인 유지 (Finnhub → yfinance → Graceful Empty)

### Next Steps

1. 사용자 확대 — 부모님 외 직장인 3~5명한테 써보게 하고, 브리핑이 실제 판단에 도움 되는지 확인
2. 배포 안정화 — ngrok(로컬) → 클라우드 서버로 옮겨서 상시 접근 가능하게
3. Claude API 전환 — 사용자 늘면 동시 호출 제한 풀어야 함
```

### PM 관점 효과
- 계획만 세운 게 아니라 실제로 했다는 게 보임
- 된 것 / 안 된 것 / 다음에 할 것이 분리되어 있음
- Next Steps가 현실적 (배포 제약 솔직하게 인정)

## 수정 시 주의사항

1. **알림/Push 언급 금지** — 배포 제약으로 실사용 불가, 언급하면 공허해짐
2. **텔레그램 언급 금지** — 같은 이유
3. **기능 나열 금지** — 새 기능은 "왜 만들었는지"와 연결될 때만 언급
4. **기술 스택 업데이트 최소화** — Haiku 전환 등은 "현재 상태" 테이블에서 한 줄로 충분
5. **톤 유지** — 현재 페이지의 "제약 속 판단" 톤을 유지. 자랑이 아닌 과정 서술
